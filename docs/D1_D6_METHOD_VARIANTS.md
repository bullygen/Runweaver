# Документация по вариантам этапов D1–D6

Документ описывает только вычислительные этапы D1–D6. Цель описания — сделать конфигурацию пайплайна читаемой без обращения к специальной литературе. Все имена аргументов CLI соответствуют полям `PipelineConfig` в `smbh_cv_pipeline/config.py`.

## 1. Общий протокол запуска

Пайплайн хранит результат каждого этапа на диске. Следующий этап читает уже сохраненные файлы. Это сделано для того, чтобы память, занятая тяжелым этапом, освобождалась до запуска следующего этапа.

Полный запуск с рекомендуемой конфигурацией для рабочей машины 32 GB RAM, 12 CPU cores:

```bash
python smbh_cv_run.py all \
  --out runs/main_32gb \
  --clean \
  --n-images 71 \
  --seed 7 \
  --workers-generate 4 \
  --workers-d1 6 \
  --workers-d2 4 \
  --workers-d3 2 \
  --workers-d4 6 \
  --workers-d5 2 \
  --workers-d6 6 \
  --workers-viz 1 \
  --d1-mask-method percentile_cc \
  --d1-edge-method legacy_laplace_positive \
  --d1-threshold-method positive \
  --d1-morphology-method legacy_control_open \
  --no-d1-skeletonize \
  --d2-method sparse_rht_stratified \
  --d2-vote-weight mean \
  --d3-method ph_union_find_sparse \
  --d3-threshold-method relative \
  --d3-relative-threshold 0.18 \
  --d3-max-candidates 24 \
  --d4-method profile_harmonic \
  --d4-max-init-candidates 24 \
  --d5-loss soft_l1 \
  --d5-residual-weighting ring_support \
  --d5-fit-stride 8 \
  --d6-method merge_fdr_bh_amplitude \
  --d6-fdr-alpha 0.05 \
  --d6-fdr-no-covar-action keep_all \
  --make-plots
```

Для проверки воспроизводимости одного изображения:

```bash
python smbh_cv_run.py benchmark_one \
  --out runs/check_one \
  --clean \
  --d1-edge-method legacy_laplace_positive \
  --d1-threshold-method positive \
  --d1-morphology-method legacy_control_open \
  --d3-method ph_union_find_sparse \
  --make-plots
```

Если выбран плотный persistent-homology backend, например `--d3-method ph_cripser_dense`, число воркеров D3 должно быть `1`. Один такой процесс может занимать до 10 GB RAM и больше.

## 2. D1: предобработка и выделение граничных пикселей

D1 получает изображение `I[y, x]`. Результат D1 — бинарная карта `B[y, x]` и карта весов `W[y, x]`. Бинарная карта задает пиксели, из которых D2 будет брать точки для RHT. Карта весов задает вклад пикселей в weighted RHT.

Файл результата:

```text
D1_preprocess/<image_id>/d1_edges.npz
```

Содержимое:

```text
binary        бинарная карта 0/1
weights       неотрицательная карта весов в диапазоне [0, 1]
edge_response исходный ответ граничного фильтра
```

### 2.1. `--d1-mask-method`, поле `d1_mask_method`

Задает способ убрать яркую компоненту джета/фона до поиска кольцевых границ.

`none`.

Операция не выполняется. В фильтр границ поступает исходное изображение.

`rect_max`.

Находится пиксель максимальной яркости:

```text
(y*, x*) = argmax I[y, x]
```

Квадратная область

```text
|x - x*| <= h, |y - y*| <= h
```

заменяется медианой изображения. Здесь `h = d1_rect_half_size`.

`percentile_cc`.

Вычисляется порог яркой области:

```text
T = percentile(I, d1_jet_percentile)
```

Строится маска `I >= T`. В ней ищутся связные компоненты. Выбирается компонента с максимальной суммарной яркостью. Эта компонента расширяется диском радиуса `d1_rect_half_size` и заменяется медианой изображения.

### 2.2. `--d1-edge-method`, поле `d1_edge_method`

Задает фильтр, который преобразует изображение после маскирования в карту граничного ответа `E[y, x]`.

`legacy_laplace_positive`.

Это исходный дешевый метод из файлов проекта. Он применяет свертку с ядром

```text
K = [[ 0, -1,  0],
     [-1,  4, -1],
     [ 0, -1,  0]]
```

Граничный ответ:

```text
E = I_masked * K
E[y, x] = 4 I[y, x] - I[y-1, x] - I[y+1, x] - I[y, x-1] - I[y, x+1]
```

Положительный ответ появляется там, где центральный пиксель больше среднего значения четырех соседей. Для кольца это часто соответствует внутренней или внешней границе яркой полосы. Рекомендуемая пара для этого метода:

```text
--d1-threshold-method positive
--d1-morphology-method legacy_control_open
```

`log_mad`.

Для каждого масштаба `sigma` из `d1_edge_sigmas` вычисляется

```text
E_sigma = | Laplace(G_sigma * I_masked) |
```

где `G_sigma * I_masked` — изображение после гауссова сглаживания с шириной `sigma`. Итоговая карта:

```text
E[y, x] = max_sigma E_sigma[y, x]
```

Метод ищет границы разной толщины. Он дороже исходного фильтра, потому что выполняет несколько сглаживаний.

`dog`.

Для каждого `sigma` вычисляется разность двух сглаженных изображений:

```text
E_sigma = | G_sigma * I_masked - G_(1.6 sigma) * I_masked |
E[y, x] = max_sigma E_sigma[y, x]
```

Метод реагирует на структуры, которые видны на масштабе `sigma`, но исчезают при более сильном сглаживании.

`sobel`.

Вычисляются конечные разности по двум направлениям:

```text
Sx[y, x] = горизонтальная разность яркости
Sy[y, x] = вертикальная разность яркости
E[y, x] = sqrt(Sx[y, x]^2 + Sy[y, x]^2)
```

Метод выделяет места с большим изменением яркости.

`laplace_sign`.

Вычисляется дискретный лапласиан и сохраняется только положительная часть:

```text
E = max(Laplace(I_masked), 0)
```

Это близко к `legacy_laplace_positive`, но использует реализацию `scipy.ndimage.laplace`.

### 2.3. `--d1-threshold-method`, поле `d1_threshold_method`

Преобразует `E[y, x]` в бинарную карту `B[y, x]`.

`positive`.

Используется порог `0`:

```text
B[y, x] = 1, если E[y, x] > 0
B[y, x] = 0, иначе
```

Это исходное правило для `legacy_laplace_positive`.

`mad`.

Вычисляются медиана и робастная оценка масштаба:

```text
m = median(E)
s = 1.4826 * median(|E - m|)
T = m + d1_tau * s
```

Бинаризация:

```text
B[y, x] = 1, если E[y, x] > T
```

`percentile`.

Порогом является перцентиль:

```text
T = percentile(E, d1_percentile)
B[y, x] = 1, если E[y, x] > T
```

`sauvola`.

Для каждого пикселя вычисляется локальный порог в окне вокруг пикселя. Бинаризация использует свой порог для каждой позиции. Метод применяется, когда фон меняется по изображению.

### 2.4. `--d1-morphology-method`, поле `d1_morphology_method`

Удаляет мелкие шумовые области из бинарной карты.

`none`.

Бинарная карта не изменяется.

`remove_small`.

Удаляются связные компоненты, площадь которых меньше `d1_min_area`.

`open_close`.

Сначала удаляются мелкие компоненты. Затем выполняется открытие и закрытие бинарной карты структурным элементом радиуса 1 пиксель. Открытие удаляет одиночные шумовые пиксели. Закрытие заполняет малые разрывы.

`legacy_control_open`.

Это исходный протокол из проекта. Повторяется бинарное открытие ядром `3 x 3`. После каждой итерации считается доля единиц в контрольной области:

```text
q_n = number_of_ones_in_control_region / control_region_size
```

Итерации останавливаются, если

```text
q_n <= d1_legacy_badpix
```

или достигнуто `d1_legacy_max_iter`.

### 2.5. Остальные аргументы D1

`--d1-edge-sigmas`, `d1_edge_sigmas`.

Список масштабов для `log_mad` и `dog`. Формат строки: `"1.0,1.5,2.0,3.0"`.

`--d1-tau`, `d1_tau`.

Коэффициент в пороге `mad`. Чем больше значение, тем меньше пикселей пройдет в бинарную карту.

`--d1-percentile`, `d1_percentile`.

Перцентиль для `threshold_method=percentile`.

`--d1-min-area`, `d1_min_area`.

Минимальная площадь связной компоненты для удаления маленьких объектов.

`--d1-skeletonize / --no-d1-skeletonize`, `d1_skeletonize`.

Если включено, бинарные линии утончаются до скелета. Это уменьшает число точек для D2. Для старого метода можно выключать, чтобы поведение было ближе к исходному проекту.

`--d1-jet-percentile`, `d1_jet_percentile`.

Перцентиль яркости для поиска джета в `percentile_cc`.

`--d1-rect-half-size`, `d1_rect_half_size`.

Полуразмер прямоугольника для `rect_max` и радиус расширения компоненты для `percentile_cc`.

`--d1-legacy-badpix`, `d1_legacy_badpix`.

Допустимая доля единиц в контрольной области для `legacy_control_open`.

`--d1-legacy-max-iter`, `d1_legacy_max_iter`.

Максимальное число итераций открытия для `legacy_control_open`.

## 3. D2: Randomized Hough Transform для окружностей

D2 получает набор граничных точек:

```text
P = {(x_i, y_i): B[y_i, x_i] = 1}
```

На каждой итерации выбираются три разные точки. Через три неколлинеарные точки проводится единственная окружность. Она задает параметры:

```text
theta = (x0, y0, R)
```

Эти параметры получают голос в аккумуляторе.

Файл результата:

```text
D2_hough/<image_id>/d2_sparse_accumulator.npz
```

Содержимое:

```text
accumulator: array shape (K, 4)
columns: x0, y0, R, votes
```

В этой версии аккумулятор хранится разреженно. Пустые ячейки не записываются.

### 3.1. Отличие нового RHT от исходного плотного RHT

Исходная версия строила плотный массив:

```text
U[x_bin, y_bin, R_bin]
```

Каждый голос увеличивал одну ячейку этого массива. Преимущество: можно сразу смотреть срезы и проекции массива. Недостаток: память зависит от полного размера сетки:

```text
memory ~ Nx * Ny * Nr
```

Новая версия хранит только непустые ячейки:

```text
rows[k] = (x0_k, y0_k, R_k, votes_k)
```

Память зависит от числа непустых ячеек `K`, а не от полного объема сетки. Это дешевле по памяти, но для картинки надо восстановить проекции. В модуле визуализации это исправлено: из sparse rows строятся непрерывные цветные карты:

```text
XY[x, y] = sum_R U[x, y, R]
XR[x, R] = sum_y U[x, y, R]
YR[y, R] = sum_x U[x, y, R]
```

На эти карты нанесены локальные максимумы. Поэтому теперь можно смотреть те же области концентрации голосов, но без хранения полного куба.

Дополнительные отличия нового RHT:

1. Радиус ограничен интервалом `[d2_r_min, d2_r_max]`.
2. Тройки с малой площадью треугольника отбрасываются.
3. В режиме `sparse_rht_stratified` точки берутся из разных угловых секторов.
4. Голос может иметь вес, зависящий от D1 edge response.
5. Генератор случайных чисел фиксируется через `seed`, поэтому результат воспроизводим.

### 3.2. `--d2-method`, поле `d2_method`

`sparse_rht`.

Три точки выбираются случайно из всех edge pixels. Условие: индексы точек должны быть разными.

`sparse_rht_stratified`.

Изображение делится на `d2_n_sectors` угловых секторов относительно центра изображения. Тройки выбираются так, чтобы точки были из разных секторов. Это уменьшает число троек, в которых точки лежат близко друг к другу и плохо задают окружность.

### 3.3. `--d2-vote-weight`, поле `d2_vote_weight`

`none`.

Каждая допустимая тройка дает голос 1.

`mean`.

Если веса трех точек равны `w1, w2, w3`, то голос:

```text
vote = (w1 + w2 + w3) / 3
```

`product`.

Голос:

```text
vote = w1 * w2 * w3
```

Этот режим сильнее подавляет тройки, где хотя бы одна точка имеет малый edge response.

### 3.4. Остальные аргументы D2

`--d2-votes-fraction`, `d2_votes_fraction`.

Задает целевое число попыток как долю от `N^3`, где `N = min(nx, ny)`:

```text
N_votes = d2_votes_fraction * N^3
```

`--d2-max-votes`, `d2_max_votes`.

Верхняя граница числа принятых голосов.

`--d2-min-triangle-area`, `d2_min_triangle_area`.

Минимальная площадь треугольника из трех выбранных точек. Если площадь меньше, окружность считается плохо определенной и тройка отбрасывается.

`--d2-center-bin-px`, `d2_center_bin_px`.

Размер ячейки для координат центра. Если `x0=101.4` и bin size `1`, центр попадает в bin `101`.

`--d2-radius-bin-px`, `d2_radius_bin_px`.

Размер ячейки для радиуса.

`--d2-r-min`, `d2_r_min`.

Минимальный допустимый радиус окружности.

`--d2-r-max`, `d2_r_max`.

Максимальный допустимый радиус окружности.

`--d2-n-sectors`, `d2_n_sectors`.

Число угловых секторов для `sparse_rht_stratified`.

## 4. D3: выбор кандидатов из аккумулятора

D3 получает строки sparse accumulator:

```text
(x0, y0, R, score)
```

Результат D3 — список кандидатов окружностей.

Файл результата:

```text
D3_candidates/<image_id>/d3_candidates.json
```

### 4.1. `--d3-method`, поле `d3_method`

`peak_nms`.

Строки аккумулятора сортируются по `score`. Далее применяется правило подавления близких кандидатов. Кандидат отбрасывается, если уже выбран другой кандидат с условиями:

```text
distance((x0, y0), (x0_selected, y0_selected)) <= d3_nms_dx
abs(R - R_selected) <= d3_nms_dr
```

`bootstrap_nms`.

То же, что `peak_nms`, но порог score оценивается повторными выборками из набора score. Это дает более строгий порог, когда распределение голосов содержит много слабых случайных максимумов.

`ph_safe_proxy`.

Берутся top-K строк аккумулятора. Полный трехмерный массив не строится. После оценки памяти плотного массива выполняется безопасное NMS. Этот режим оставлен как защита от случайного запуска тяжелого PH.

`ph_union_find_sparse`.

Это H0-only persistent-homology режим без плотного кубического комплекса. Он работает только по занятым sparse-ячейкам аккумулятора.

Протокол:

1. Каждая ячейка `(x_bin, y_bin, R_bin)` считается вершиной с высотой `score`.
2. Ячейки добавляются в порядке убывания `score`.
3. Новая ячейка соединяется с уже добавленными соседями. Соседями считаются ячейки, у которых каждая координата отличается не более чем на 1 bin.
4. Если соединяются две компоненты, компонент с меньшей высотой рождения считается исчезнувшим.
5. Для исчезнувшего компонента записывается:

```text
birth = score максимума компонента
death = текущий score при соединении
persistence = birth - death
```

Большое значение `persistence` означает, что максимум был отделен от более высокого максимума на большом диапазоне уровней score. Для задачи D3 это численный признак устойчивого локального максимума RHT.

Память режима:

```text
memory ~ O(K)
```

где `K` — число sparse-ячееек, взятых из аккумулятора. Полный массив `Nx * Ny * Nr` не создается.

`ph_cripser_dense`.

Опциональный режим для библиотеки `cripser`, если она установлена. Он строит плотный объем и поэтому может потреблять много памяти. Его не рекомендуется использовать на 32 GB машине, если `Nx`, `Ny` или диапазон `R` велики. Для штатного запуска используйте `ph_union_find_sparse`.

### 4.2. `--d3-threshold-method`, поле `d3_threshold_method`

`relative`.

Порог:

```text
T = d3_relative_threshold * max(score)
```

`quantile`.

Порог:

```text
T = quantile(score, d3_quantile)
```

`bootstrap`.

Многократно берутся случайные подвыборки score. В каждой подвыборке записывается максимум. Порогом становится квантиль этих максимумов:

```text
T = quantile(max_scores, d3_bootstrap_quantile)
```

### 4.3. Остальные аргументы D3

`--d3-relative-threshold`, `d3_relative_threshold`.

Коэффициент для `threshold_method=relative`.

`--d3-quantile`, `d3_quantile`.

Квантиль для `threshold_method=quantile`.

`--d3-bootstrap-quantile`, `d3_bootstrap_quantile`.

Квантиль bootstrap-максимумов.

`--d3-bootstrap-repeats`, `d3_bootstrap_repeats`.

Число повторов bootstrap.

`--d3-nms-dx`, `d3_nms_dx`.

Радиус подавления по координатам центра.

`--d3-nms-dr`, `d3_nms_dr`.

Радиус подавления по радиусу кольца.

`--d3-max-candidates`, `d3_max_candidates`.

Жесткий верхний предел числа кандидатов.

`--d3-expected-max-rings`, `d3_expected_max_rings`.

Оценка максимального числа реальных колец. Внутренний предел кандидатов считается как `min(d3_max_candidates, 3 * d3_expected_max_rings)`.

`--d3-top-k-for-ph`, `d3_top_k_for_ph`.

Сколько лучших sparse-ячеек передавать в `ph_union_find_sparse` или `ph_safe_proxy`.

`--d3-ph-memory-limit-gb`, `d3_ph_memory_limit_gb`.

Предельная оценка памяти для плотных PH-режимов. Если оценка выше этого значения, dense backend не должен запускаться.

## 5. D4: начальные параметры модели

D4 переводит кандидаты `(x0, y0, R)` в полные параметры кольца:

```text
(A, R, sigma, B, phi, x0, y0)
```

Файл результата:

```text
D4_initialization/<image_id>/d4_initial_params.json
```

### 5.1. `--d4-method`, поле `d4_method`

`constants`.

Используются фиксированные значения:

```text
A = 0.035
sigma = 7.0
B = 0.5
phi = 0.0
x0, y0, R берутся из D3
```

`profile_harmonic`.

Для каждого кандидата строится выборка яркости в кольцевой области вокруг `(x0, y0, R)`.

Радиальный профиль:

```text
P(r) = median_angle I(x0 + r cos a, y0 + r sin a) - background
```

Новый радиус берется в точке максимума профиля:

```text
R = argmax_r P(r)
```

Ширина оценивается по ширине профиля на половине максимума:

```text
sigma = FWHM / 1.665109222
```

Асимметрия берется из первой угловой гармоники. Для угловых значений `v(a)`:

```text
C = sum_a v(a) cos(a)
S = sum_a v(a) sin(a)
phi = atan2(S, C) + pi
B = 2 sqrt(C^2 + S^2) / sum_a v(a)
```

Амплитуда оценивается из высокого перцентиля яркости в кольцевой полосе:

```text
A = 2 pi * percentile_95(v) / (1 + B)
```

### 5.2. Остальные аргументы D4

`--d4-strip-half-width`, `d4_strip_half_width`.

Полуширина кольцевой полосы для углового профиля.

`--d4-radial-window`, `d4_radial_window`.

Полуширина радиального окна вокруг исходного `R` из D3.

`--d4-n-angle-bins`, `d4_n_angle_bins`.

Число угловых точек для расчета первой гармоники.

`--d4-max-init-candidates`, `d4_max_init_candidates`.

Сколько кандидатов D3 передавать в начальные параметры фитирования.

## 6. D5: нелинейное фитирование

D5 подгоняет параметры модели изображения. Модель равна сумме фоновой компоненты и колец:

```text
M[x, y] = J[x, y] + sum_i Ring_i[x, y]
```

Кольцо:

```text
Ring_i = A_i * (1 - B_i cos(angle - phi_i)) / (2 pi) * exp(-(r - R_i)^2 / sigma_i^2)
```

Оптимизация минимизирует вектор остатков:

```text
residual[x, y] = weight[x, y] * (M[x, y] - I[x, y]) / noise_scale
```

Файл результата:

```text
D5_fit/<image_id>/d5_fit.json
```

### 6.1. `--d5-engine`, поле `d5_engine`

`scipy`.

Используется `scipy.optimize.least_squares`. Других активных backend в этой версии нет.

### 6.2. `--d5-loss`, поле `d5_loss`

Задает функцию штрафа для остатка `z = residual^2`.

`linear`.

Обычная сумма квадратов. Большие остатки сильно влияют на результат.

`soft_l1`.

Для малых остатков близко к `linear`. Для больших остатков рост штрафа замедляется. Это уменьшает влияние отдельных ярких выбросов.

`huber`.

До масштаба `f_scale` работает как сумма квадратов. После масштаба `f_scale` штраф растет медленнее.

`cauchy`.

Сильнее подавляет большие остатки, чем `soft_l1`.

`arctan`.

Еще сильнее ограничивает вклад очень больших остатков.

### 6.3. `--d5-residual-weighting`, поле `d5_residual_weighting`

`uniform`.

Все пиксели имеют вес 1.

`ring_support`.

Пиксели около начальных колец получают вес 1. Остальные пиксели получают вес 0.25. Для кольца область поддержки:

```text
|r - R| <= max(2.5 sigma, 4 px)
```

`inverse_background`.

Вес обратно пропорционален квадратному корню фоновой модели:

```text
weight = 1 / sqrt(background + 1e-6)
```

### 6.4. Остальные аргументы D5

`--d5-max-nfev`, `d5_max_nfev`.

Максимальное число вычислений функции остатков.

`--d5-fit-background / --no-d5-fit-background`, `d5_fit_background`.

Если включено, параметры фоновой компоненты также оптимизируются.

`--d5-f-scale`, `d5_f_scale`.

Масштаб перехода для robust loss. Чем меньше значение, тем раньше большие остатки начинают подавляться.

`--d5-fit-stride`, `d5_fit_stride`.

Фитирование выполняется на подвыборке пикселей:

```text
I_fit = I[::stride, ::stride]
```

Это ускоряет D5. После оптимизации модель сохраняется на полном изображении.

`--d5-local-then-global / --no-d5-local-then-global`, `d5_local_then_global`.

Аргумент зарезервирован. В текущем коде отдельная локальная стадия не реализована. Значение не меняет результат.

D5 также пытается оценить стандартные ошибки параметров по матрице производных остатка по параметрам. Для амплитуды кольца это величина `sigma_A`, которая нужна D6-методам `fdr_bh_amplitude` и `merge_fdr_bh_amplitude`. Оценка считается линейным приближением. Она наиболее корректна при `--d5-loss linear`. При `soft_l1`, `huber`, `cauchy`, `arctan` она остается диагностикой, но не является строгой вероятностной ошибкой. Если матрица вырожденная, D5 записывает `covar_available = false`.

## 7. D6: отбор и объединение после фитирования

D6 получает fitted rings из D5. Результат — финальный список колец.

Файл результата:

```text
D6_prune/<image_id>/d6_final.json
```

### 7.1. `--d6-method`, поле `d6_method`

`none`.

Все кольца из D5 сохраняются.

`amplitude`.

Кольцо сохраняется, если:

```text
A >= d6_amp_min
```

При этом число колец не опускается ниже `d6_min_artifacts`.

`delta_bic`.

Для каждого кольца сравниваются две модели: с кольцом и без него. Пусть

```text
RSS_full = sum (M_full - I)^2
RSS_without = sum (M_without_ring - I)^2
n = number of pixels
```

Считается величина:

```text
delta_bic_proxy = n * log(RSS_without / RSS_full) - 7 * log(n)
```

Кольцо сохраняется, если:

```text
delta_bic_proxy > d6_delta_bic_threshold
```

`merge_delta_bic`.

Сначала объединяются дубли. Затем применяется правило `delta_bic`.

Два кольца считаются дублями, если:

```text
distance((x0_i, y0_i), (x0_j, y0_j)) <= d6_merge_center_px
abs(R_i - R_j) <= d6_merge_radius_px
```

Из дублей сохраняется кольцо с большим `source_confidence`, если он есть, иначе с большей амплитудой.

`fdr_bh_amplitude`.

Это вариант исходного отбора из старого пайплайна. Для каждого кольца используется амплитуда `A` и стандартная ошибка амплитуды `sigma_A`, записанная этапом D5 в `stderr_artifacts`. Проверяется гипотеза `A = 0` против варианта `A > 0`.

Для кольца `i`:

```text
z_i = A_i / sigma_A_i
p_i = P(Z >= z_i), где Z имеет нормальное распределение с mean = 0 и std = 1
```

Затем p-value сортируются по возрастанию:

```text
p_(1) <= p_(2) <= ... <= p_(m)
```

Для уровня `alpha = d6_fdr_alpha` находится максимальный индекс `k`, для которого:

```text
p_(k) <= alpha * k / m
```

Сохраняются кольца с:

```text
p_i <= p_(k)
```

Если D5 не смог оценить ковариацию, применяется `d6_fdr_no_covar_action`. Значение по умолчанию `keep_all` ничего не удаляет, потому что удаление без ошибок амплитуд не является FDR.

`merge_fdr_bh_amplitude`.

Сначала объединяются дубли по тем же правилам, что в `merge_delta_bic`. Затем применяется `fdr_bh_amplitude`. Этот режим ближе всего к исходной логике проекта: сначала убираются очевидные дубли одного и того же кольца, затем выполняется Benjamini–Hochberg FDR по амплитудам.

### 7.2. Остальные аргументы D6

`--d6-min-artifacts`, `d6_min_artifacts`.

Минимальное число колец, которое нельзя удалить pruning-ом.

`--d6-amp-min`, `d6_amp_min`.

Минимальная амплитуда для `d6_method=amplitude`.

`--d6-delta-bic-threshold`, `d6_delta_bic_threshold`.

Порог для `delta_bic_proxy`.

`--d6-fdr-alpha`, `d6_fdr_alpha`.

Уровень Benjamini-Hochberg FDR для `fdr_bh_amplitude` и `merge_fdr_bh_amplitude`. Рекомендуемое стартовое значение: `0.05`.

`--d6-fdr-no-covar-action`, `d6_fdr_no_covar_action`.

Действие, если D5 не записал корректные ошибки амплитуды.

```text
keep_all            ничего не удалять
amplitude           применить простой порог A >= d6_amp_min
drop_min_amplitude  удалить одно кольцо с минимальной A
```

Рекомендуемое значение: `keep_all`. Причина: Benjamini-Hochberg требует p-value. Если `sigma_A` нет, p-value не определены.

`--d6-merge-center-px`, `d6_merge_center_px`.

Максимальное расстояние центров для признания двух колец дублями.

`--d6-merge-radius-px`, `d6_merge_radius_px`.

Максимальная разница радиусов для признания двух колец дублями.

## 8. Рекомендации по workers для 32 GB RAM и 12 ядер

Рекомендация дана для изображений 256 x 256 и разреженного RHT. Если размер изображения увеличивается, сначала уменьшайте число воркеров D3 и D5.

```text
generate: 4 workers
D1:       6 workers
D2:       4 workers
D3:       2 workers для ph_union_find_sparse или peak_nms
D3:       1 worker  для ph_cripser_dense или любого dense PH
D4:       6 workers
D5:       2 workers
D6:       6 workers
viz:      1 worker
stats:    1 worker
```

Причины:

1. D1 использует массивы размера изображения и быстро освобождает память. Можно запускать много процессов.
2. D2 выполняет много случайных троек и хранит sparse accumulator. Обычно CPU-bound, но память умеренная.
3. D3 в `ph_union_find_sparse` хранит только top-K sparse bins. Два процесса обычно безопасны. Для dense PH один worker обязателен.
4. D5 вызывает численную оптимизацию. Каждый процесс многократно строит модель. Для 12 ядер лучше не запускать много D5 одновременно.
5. Визуализация создает несколько matplotlib-фигур и может держать крупные массивы до сохранения PNG. Один worker безопаснее.

Если используются BLAS/OpenMP-библиотеки, перед запуском на много workers рекомендуется ограничить внутреннюю многопоточность:

```bash
export OMP_NUM_THREADS=1
export OPENBLAS_NUM_THREADS=1
export MKL_NUM_THREADS=1
export NUMEXPR_NUM_THREADS=1
```

## Дополнение: D6 amplitude prefilter + merge/statistical pruning

Добавлены два режима:

```text
d6_method = amplitude_merge_delta_bic
```

Протокол:

1. Для каждого fitted кольца прочитать амплитуду `A_i`.
2. Удалить кольцо, если `A_i < d6_amp_min`.
3. Если после удаления осталось меньше `d6_min_artifacts`, сохранить самые большие по `A_i` кольца до `d6_min_artifacts`.
4. Выполнить merge дублей по `d6_merge_center_px` и `d6_merge_radius_px`.
5. Для оставшихся колец посчитать `delta_bic_proxy`.
6. Удалить кольца с `delta_bic_proxy <= d6_delta_bic_threshold`, кроме forced keep по `d6_min_artifacts`.

```text
d6_method = amplitude_merge_fdr_bh_amplitude
```

Протокол:

1. Для каждого fitted кольца прочитать амплитуду `A_i`.
2. Удалить кольцо, если `A_i < d6_amp_min`.
3. Если после удаления осталось меньше `d6_min_artifacts`, сохранить самые большие по `A_i` кольца до `d6_min_artifacts`.
4. Выполнить merge дублей по `d6_merge_center_px` и `d6_merge_radius_px`.
5. Для оставшихся колец взять `sigma_A_i` из D5 по `source_fit_index`.
6. Посчитать `z_i = A_i / sigma_A_i`.
7. Посчитать `p_i = P(Z >= z_i)`.
8. Применить Benjamini-Hochberg с уровнем `d6_fdr_alpha`.
9. Если covariance недоступна, применить `d6_fdr_no_covar_action`.

Назначение обоих режимов: удалить очевидно слабые fitted компоненты до более дорогого/строгого отбора. Это полезно, если слабые ложные кольца проходят merge или портят p-value/BIC-решение.
